## 1. 一级拦截点：官方预留的 L 钩子

```lua
-- NaowhUI_SmartReminders_Widgets.lua:19

```

**原插件内仅此一处定义，且全插件没有任何调用点。**
这是一个**预留但未启用**的本地化钩子。它不能直接用作主力拦截，但必须

## 2. 二级拦截点：控件工厂（主力）

### 2.1 `UI.ShowWidgetTooltip(label, text, opts)` — Widgets.lua:45

```lua
function UI.ShowWidgetTooltip(label, text, opts)
    -- ... 抑制检查 ...
    if type(text) == "function" then text = text() end   -- L56
    if not text or text == "" then return end            -- L57
    ...
    tt.text:SetText(text)                                -- L62
```

**关键**：`text` 可为函数。翻译必须插在 **L56 之后**（即 `type(text)=="function"` 判断之后、
`SetText` 之前）。`label` 本身不渲染（仅用于锚定位置），**不需要翻译**。

覆盖策略：包装函数，在入口处对 `type(text) == "function"` 的不做处理（交由原函数求值），
对字符串直接查表；最省事的做法是在包装里判断后转发。

> ⚠️ 注意 L57 的 `if not text or text == "" then return end` 在 `text` 是函数时**不会**误判
> （函数非 nil 非 ""）。包装时必须复刻这个短路语义，否则会改变原行为。

### 2.2 `W:DualRow(parent, y, leftCfg, rightCfg)` — Widgets.lua:521

cfg 是**表**，翻译的是它的字段，不是整个表：

| 字段 | 说明 |
|---|---|
| `cfg.text` | 行标签（`BuildRegion` L488 `lbl:SetText(cfg.text or "")`） |
| `cfg.tooltip` | 悬停提示（L507 `local tip = disabled and cfg.disabledTooltip or cfg.tooltip`） |
| `cfg.disabledTooltip` | 禁用态提示 |
| `cfg.values` | **仅下拉**：值→显示串映射（见 2.3） |

**陷阱：行缓存**
```lua
-- L522-523
local key = "row:" .. leftCfg.type .. ":" .. (leftCfg.text or "") .. ":"
    .. (rightCfg and (rightCfg.type .. ":" .. (rightCfg.text or "")) or "")
```

行按 **`cfg.text` 的英文原文**做缓存键。若在进入 `DualRow` 之前就把 `cfg.text` 改成中文，
缓存键会随之改变 → 同一页重复渲染时命中缓存失败 → 每次都新建 Frame → **内存泄漏 + 行叠行**。

**因此翻译必须在 `DualRow` 内部进行，不可在调用点预先改写 cfg。**
（这正是"运行时拦截"优于"源码补丁"的核心原因之一。）

**陷阱：`_refresh(newCfg)`**
```lua
-- L492-496
rgn._refresh = function(newCfg)
    UpdateConfig(cfg, newCfg)
    local off = ...
    lbl:SetText(cfg.text or "")   -- ← 再次从 cfg.text 取
```
复用行时 `UpdateConfig` 把新 cfg 拷进旧 cfg，`lbl:SetText` 再从 `cfg.text` 读一次。
若 `cfg.text` 已被换成中文，`UpdateConfig` 的 `prior ~= src[key]` 判断仍成立（这是
纯表内拷贝，与翻译无关），**只要翻译发生在 `BuildRegion` 的 `SetText` 层就安全**。
但若翻译发生在 `DualRow` 入口改写 `cfg.text`，则缓存键与实际渲染文本都会变，
`_refresh` 会拿中文去比较英文，导致刷新失配。

→ **最终方案：不改 cfg，而是包装 `ns.Font`，在 FontString 的 `SetText` 层面翻译。**
   详见 §3。

### 2.3 `UI.BuildDropdownControl(parent, ddW, fLevel, values, order, get, set)` — Widgets.lua:185

```lua
lbl:SetText(values[v] or tostring(v or ""))            -- L209 按钮显示
desc:CreateRadio(values[key] or tostring(key), ...)    -- L254 菜单项显示
```

**`values` 是「逻辑键 → 显示串」的映射，翻译的只能是 `values[k]`，绝不能动 `k`。**

- `k` 会被 `set(k)` 写进存档、参与 `get() == key` 比较
- 覆写 `values` 表本身是**安全**的（原表只在 `DualRow` 内被读取，不回流）
- 但更稳的做法仍是只包 `SetText`，因为 `CreateRadio` 的显示串走 Blizzard 的菜单系统，
  不经过我们的 FontString 拦截 —— **这一处必须单独处理**。

已知需要翻译的 `values` 实例：
- `{ timeline = "Blizzard Timeline", bigwigs = "BigWigs", dbm = "DBM" }`（主文件:6636）
- `{ TOP = "Above the Icon", BOTTOM = "Below the Icon", LEFT = "Left of the Icon", RIGHT = "Right of the Icon" }`（主文件:6832）
- `{ [100] = "100%  (default)", [90] = "90%", ... }`（主文件:6880，含数字键）
- `{ [""] = "Default (Naowh)" }` + LSM 字体名（主文件:6785，**LSM 名不可翻**）
- `{ Added = "Applied", ApplicationsIncreased = "Stack increased", Removed = "Removed" }`（IntegrationOptions:130）
- `{ player = "Me", party = "Party members" }`（IntegrationOptions:133）
- `{ none = "Custom text" }`（IntegrationOptions:139）
- `UI.BuildAlertSoundTables()` 返回的 `names = { none = "None", [voice.key] = "Voice: " .. text .. " (English)" }`（Widgets:679）

> **`names` 表的安全边界**：`names["sm:" .. name] = name` 里的 LSM 音效名**不能翻**
> （`SoundPathFor` 用 key 查 `paths`，`names` 只作显示）。但 `names[key]` 的显示串可翻。

## 3. 兜底拦截点：`ns.Font(parent, size, flags, color)` — Core.lua:70

```lua
function ns.Font(parent, size, flags, color)
    local c = color or ns.THEME.fg
    local fs = parent:CreateFontString(nil, "OVERLAY")
    fs:SetFont(ns.UIFontPath(), size, flags or "")
    fs:SetTextColor(c.r, c.g, c.b, 1)
    return fs
end
```

**这是全插件所有文字的统一出口。** 包装它即可：

1. 记录返回的 FontString 到弱引用表（`setmetatable({}, {__mode="k"})`）
2. 覆写该 FontString 的 `SetText` 方法为一个查表版本

```lua
local origSetText = fs.SetText
fs.SetText = function(self, s, ...)
    if type(s) == "string" then s = L(s) end
    return origSetText(self, s, ...)
end
```

**风险**：FontString 不是 Frame，`SetText` 是 metatable 方法；直接赋值到实例上在
WoW 客户端**可行**（WoW 的 userdata 允许实例字段遮蔽方法），但这需要实机验证。
若不可行，退路是 hook `SetText` 的 C 方法 —— 不可行（受保护 API）。

**必须保留的退路**：若实例遮蔽不可用，则在每个具体出口（2.1~2.8）逐点覆盖。
本工程**双轨实现**：主用实例遮蔽 + 显式出口覆盖，互不冲突（`L()` 幂等）。

## 4. 特殊拦截点：返回值需翻译的构造函数

以下函数**返回值会被上游 `%s` 回填进英文模板**。翻译必须发生在**返回值层面**，
否则中文串会被塞进英文句子造成中英混杂。

### 4.1 `ns.SpecName(specID)` — Core.lua:147
```lua
function ns.SpecName(specID)
    ...
    local ok, _, name, _, _, _, _, className = pcall(GetSpecializationInfoByID, id)
    if not (ok and name) then return "Spec " .. id end    -- ← "Spec %d" 需翻译
    if className and className ~= "" then return name .. " " .. className end
    return name                                            -- ← 客户端已本地化，不改
end
```
`name` / `className` 来自客户端，**在 zhCN 客户端下已是中文**，不要动。
只有 `"Spec " .. id` 这个兜底串需要翻译。

**消费者**（证明必须从返回值层面拦截）：
```lua
-- Bosses.lua:2973-2976
("This profile has %d %s set up, but none of them on %s -- abilities are saved per spec. ...")
    :format(total, total == 1 and "ability" or "abilities", ns.SpecName(specID) or "this spec")
```

### 4.2 `ns.EncounterSetForKind(isRaid)` — Bosses.lua:3082
```lua
return set, isRaid and "Raid Boss" or "Dungeon Boss"    -- L3085 / L3095
```
返回值 `scopeWord` 被传入 `ns.ShowCopyBindingsPopup` 并被消费：
```lua
-- Bosses.lua:3107-3109
head:SetText(allMode and ("Copy Every %s From"):format(scopeWord or "Boss") or "Copy Abilities From")
-- L3125-3129
hint:SetText(allMode and ("Every %s that spec has set up is copied, ..."):format((scopeWord or "boss"):lower()) or "...")
-- L3144-3145
chkLbl:SetText(("Every %s, not just %s"):format((scopeWord or "boss"):lower(), bossName or "this one"))
```

> **`%s` 回填 + `:lower()` 的双重陷阱**：`("Every %s, not just %s")` 把 `scopeWord`
> 转小写后插入英文句子。中文没有大小写，`("首领"):lower()` 返回自身，安全。
> **但是**：如果翻译成「每个 %s，而不只是 %s」，`scopeWord` 的中文直接填入即可。
> **绝对不能**把 `scopeWord` 翻成带引号或带定冠词的串。

**结论**：`ns.EncounterSetForKind` 的第二个返回值必须翻译。`scopeWord` 语义 =
「首领类别名词」（"Raid Boss" → "团队首领"、"Dungeon Boss" → "地下城首领"）。

## 6. 页签名翻译的**唯一**渲染点

## 10. 最终拦截策略（三轨并行，幂等）

| 轨 | 手段 | 覆盖面 | 风险 |
|---|---|---|---|
| **轨 1（主力）** | 包装 `ns.Font`，给返回的 FontString 实例挂自定义 `SetText` | 全插件所有 FontString 文字（约 95% 文本） | 依赖 WoW 允许实例字段遮蔽方法，**需实机验证** |
| **轨 2（显式）** | 包装 `ns.UI.ShowWidgetTooltip`（处理函数式 text）、`UI.BuildDropdownControl`（包 `values`）、`ns.Button`、`ns.SetButtonText`、`W:*` 各控件 | 轨 1 无法覆盖的（菜单项、动态 tooltip） | 低 |
| **轨 3（兜底）** | `L()` 幂等：中文/数字/nil/secret 原样返回 | 防止重复翻译与异常 | 无 |

**三轨全部调用同一个 `L()`**，`L()` 幂等保证重复经过不会二次翻译。

### `L()` 的四条硬性要求

1. **幂等**：`L(L(s)) == L(s)`
2. **secret 防护**：`issecretvalue(s)` 为真时**立即原样返回**，绝不 `tostring`
3. **非字符串透传**：`type(s) ~= "string"` 原样返回（nil / number / boolean / table）
4. **长文本不拆**：含 `\n` / `|c` / `%` 的串只在**整串精确匹配**时替换；
   模板匹配（`"Show %s Anchor"`）只在**已知模板**上做，不做泛化正则

### 防误翻的**白名单**原则

`L()` 只翻译**命中字典**的串。字典由 `tools/` 从扫描产物生成 + 人工审校。
**任何未命中字典的串原样返回** —— 这保证了逻辑键（页签名、存档值、FLAG_LABELS）
即使漏进 `L()` 也不会被破坏。
